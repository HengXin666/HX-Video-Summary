Open Code 深度评测：开源AI编程助手的自由与安全之道

一、核心主题概述

主讲人「小潘老师」从 Claude Code 转向 Open Code 后，系统性地对比了两款 AI 编程助手的差异，并分享了他基于 Open Code 构建的一套完整 AI 辅助开发工作流——从模型选择、权限控制、任务外包到安全沙箱，全方位展示了开源工具在灵活性和可控性上的巨大优势。

二、Open Code vs Claude Code：六大核心优势

1. 模型选择完全自由
   - Open Code 支持任意模型的 API Key，官方还提供免费模型额度（如 Gemini 2.5 可限速免费使用）
   - Claude Code 切换模型需设置环境变量并重启，且被锁定在特定模型系列内
   - Open Code 可随时在对话中动态切换模型，无需重启

2. 智能权限控制
   - Open Code 能自动检测命令的影响范围：仅涉及当前项目目录的操作直接放行，涉及全局系统的操作才会询问
   - Claude Code 采用全有或全无模式——要么每个命令都问，要么全部放行，缺乏细粒度智能判断

3. 架构师-执行器分离的任务外包体系
   - Architect（大脑风暴 Agent）：分析需求→搜索现有方案→澄清细节→生成 task.json 计划文档
   - Executor（执行器）：仅阅读 task.json，逐条执行未完成任务，极其"死板"但可靠
   - Worker（子代理）：承担具体子任务，通过层层转包保持每个代理的上下文精简
   - 天然支持"断点续传"：死机/关机后重新启动，自动从最后完成的任务处继续

4. 内置安全机制
   - TDD 开发模式：强制先写测试用例，测试全部通过才算完成，避免 AI 写出有 bug 的代码
   - Test Safety Protocol：限制文件写入仅限项目目录，禁止操作系统全局路径
   - Docker 沙箱隔离：通过容器将 AI 的操作范围限制在只有当前项目文件的环境中
   - Git 安全规则：默认不 push，除非用户明确要求；自动管理 .gitignore 避免误提交二进制文件

5. 可自定义的 Agent 类型
   - 内置 Build 模式和 Plan 模式（Tab/Shift+Tab 切换）
   - 支持自定义 Agent 类型（如"大脑风暴"Agent），可配置专属颜色和提示词
   - Plan 模式让 AI 先输出计划书，用户审核后再进入 Build 模式执行

6. 上下文管理与效率优化
   - 通过 Worker 子代理避免单一上下文过度膨胀（省 token、降低延迟）
   - 每完成一个子任务生成 progress.txt，供后续 Worker 了解进度
   - 避免"裹脚布"上下文：不同任务新建对话，用 @引用文档注入长期记忆

三、AI 辅助开发的实用技巧

1. 提问技巧
   - 直接描述原始目标 X，不要预设错误方案 Z 去提问（XY 问题）
   - 不确定时可以先说"我想做 X，想到的方法是 Z，但我不确定 Z 是否正确"
   - 不要给 AI 硬性指标（如"优化到1秒内"），而是让 AI 先分析可行性

2. 自己写代码，让 AI 审核
   - AI 写代码容易幻觉出不存在的 API 或曲解需求
   - 但 AI 审核代码非常高效——能快速发现变量命名错误、返回值未处理等问题
   - 推荐流程：人写代码 → AI 捉虫 → 人确认修改

3. 与 AI 沟通的风格准则
   - 用 must/always/don't 等强制词，不要说"为什么"
   - AI 是一次性工具（摔炮），不是长期同事，无需解释背景
   - 干活时直白指令，评估时单独开对话
   - 开始执行前先展示计划，审核通过再执行

4. 持久化记忆策略
   - 不要把所有信息塞进上下文（AI 记不住长对话）
   - 关键规范写入文档，通过 @引用 强制 AI 阅读
   - 文档 = 长期记忆，对话 = 短期记忆

5. 配置与风格规范
   - 使用 UV 而非 pip 管理 Python 包
   - 新项目用 4 空格缩进，已有项目服从现有风格
   - 代码用英文撰写，回复可用中文（方便阅读）

四、小潘老师的工具生态

1. Brain Stack：开发过程中快速捕获随机想法的工具，截图+文字记录，防止遗忘
2. 倒计时器：正数计时器追踪工作时间，到点提醒休息
3. Fish Shell Commit 助手：输入 commit 自动调用 AI 生成规范的 commit message
4. Vim 插件包：也是通过 Open Code 自动生成的

五、结论与启示

Open Code 作为开源 AI 编程助手，在灵活性、安全性和可定制性上展示出远超闭源竞品的优势：
- 模型自由让用户不再被厂商绑定
- 智能权限+沙箱隔离让 AI 可以在后台安全地执行超长期任务
- 架构师-执行器分离的工作流让复杂任务拆解为可控的子任务
- 辅以恰当的提示工程策略，AI 编程助手的效率可大幅提升

核心方法论：把 AI 当成一个服从命令、一次性使用的"智能摔炮"，用文档做长期记忆，用 @ 引用做强制输入，用 Plan→Review→Build 工作流做质量把控，用 Docker 沙箱做安全兜底。
