安全机制

四重防线：让AI安全地自主工作

TDD 开发模式

强制先写测试用例再写实现，测试全部通过才算完成。避免 AI 写出有 bug 但不自知的代码，杜绝"看起来能用但一跑就崩"。

Test Safety Protocol

限制文件系统写入仅限当前项目目录，禁止操作系统全局路径。每次 TDD 开发前强制读取安全协议文档。

Docker 沙箱隔离

容器内只有项目文件和 Open Code 配置，根目录仅有项目目录。AI 再怎么"飘"也只能破坏项目本身，动不了系统。

Git 安全规则

默认不 push（除非明确要求），自动管理 .gitignore 排除二进制文件，遵循规范化 commit message 格式。

实战技巧

AI 协作的 三个关键方法

1

直接说目标X，不要说错误方案Z

避免 XY 问题：不要预设错误路径去提问。先描述原始需求X，可附带"想到的方法是Z但不确定"，让AI判断正确做法。

2

你自己写代码，让 AI 来审核

AI 写代码容易幻觉API、曲解需求，但它审代码非常高效——变量命名错误、未处理返回值，它一眼就能看出来。

3

Plan → Review → Build 工作流

先让 AI 展示计划（Plan模式），审核脑补内容是否正确，纠正后再切换 Build 模式执行。相当于拼音输入法的候选词机制。

提示词工程

四条 核心方法论

文档 = 长期记忆

把关键规范写入文档，用 @引用 强制 AI 读取。对话只是短期记忆，不要把所有信息塞进上下文。

用强制词，不解释

使用 must / always / don't，不要解释为什么。AI 是一次性"摔炮"，以服从命令为天职，不需要了解背景故事。

新任务 = 新对话

不同任务不要共用上下文。"中世纪裹脚布"只会让 AI 遗漏关键信息。干净上下文远胜冗长历史。

规范先行，风格一致

用 UV 而非 pip；新项目 4 空格缩进；已有项目遵循现有风格。代码英文，回复中文。一次配置，持续生效。

总结收尾

核心洞察总结

开源即自由

不被厂商绑定，模型自由选择是AI编程助手的核心竞争力。

智能 > 粗暴

细粒度的权限判断胜过"全有全无"，这是工具能否安全后台运行的关键。

分工是王道

Architect → Task → Worker 的层层转包架构，把复杂任务拆解为可控的原子操作。

安全不是可选

TDD + Safety Protocol + Docker + Git 四重保障，让AI可以放心地在后台长时间运行。

AI是工具不是人

用强制词下指令，用文档做记忆，用 @ 引用做输入。把AI当成一次性的"智能摔炮"。

人写AI审 > AI写人审

AI在代码审核上的能力远超代码生成。最佳分工：人负责创造，AI负责检查。

收尾点睛

日后奋斗方向

持续优化 Safety Protocol

让AI在项目目录内的操作更自由，同时对外部系统的防护更严格。在效率与安全之间找到最佳平衡点。

完善 Agent 技能体系

构建更多专用 Agent 类型（代码审查、性能分析、文档生成），形成可复用的技能库。

量化 AI 编程效率提升

建立度量体系，追踪 AI 辅助开发的代码质量、bug率、开发速度，用数据指导工具优化。

推广开源 AI 编程文化

分享 Open Code 配置包和最佳实践，降低 AI 编程工具的使用门槛，让更多人享受开源红利。

探索多模态编程交互

结合语音、截图、白板等输入方式，让AI理解更丰富的上下文，提供更精准的编程辅助。

警示： 不要在提示词中注入无关信息（罗马神话、取名缘由等），不要向AI解释"为什么"——它是一次性工具，浪费token就是对效率和资金的浪费。

记住： Open Code 的核心价值 = 开源自由 × 智能权限 × 架构分离 × 安全沙箱。掌握这四个维度，就能把AI编程助手从"玩具"升级为"生产力引擎"。
