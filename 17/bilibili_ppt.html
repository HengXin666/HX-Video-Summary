  落地实践
以 Claude Code 为例
最轻量做法
在 CLAUDE.md 中写清楚：
· 项目背景是什么
· 希望模型做什么 / 别做什么
· 做完要跑哪些 lint / 单测 / CI
进阶方案：SDD
Spec-Driven Development
· 生成约束文件 → 明确需求
· 制定开发计划 → 拆解任务
· 实际修改 + 测试
· 每阶段更新 CLAUDE.md
SDD 本质： 就是 Honeys Engineering 的落地实践 ——每一阶段注入上下文的尽可能都是核心信息
  Key Insights
核心洞察总结
提示词工程 让大模型"听懂人话" —— 解决无引导输出问题
上下文工程 让大模型"记住上下文" —— 解决窗口腐化问题
驾驭工程 让大模型"持续按规范执行并交付成果" —— 四层协同
Agent 本质 = for 循环，循环不停，上下文持续膨胀 —— 驾驭工程在膨胀中保持核心约束
程序员的工作内容：从"写代码" → "写规则和写 Skill"
大模型越强，外壳越薄，但外壳永远需要
