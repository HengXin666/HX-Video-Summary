规则越多 → AI越难兼顾 →

03 / 07
Hook 机制原理
"按需注入"的智能安全网
CLAUDE.md 规则
常驻上下文最前端
一直占用token
距离远容易被忘
规则膨胀相互冲突
VS
Hook 钩子
执行时即时注入
按需加载不占token
最新位置高关注度
触发即提醒精准干预
本质
Hook = 在执行点附近重新注入规则，利用位置局部性让AI在犯错瞬间被提醒："我刚才是不是做错了？"
Skill
AI主动感知需求，自己决定调用。像工具箱——需要时才打开使用，用完了就释放。
Hook
AI不知道其存在，直到行为触发才会看到提醒。像安全网——平时隐形，犯错瞬间兜住。
04 / 07
Hook 四层级体系
不同风险等级，不同拦截策略
事前阻断型
 破坏性操作
拦截rm删除、敏感bash等。
含bypass标记可绕过。
不能完全堵死——逼急了AI会绕路。
事后提醒型
 风格约束
建议uv run python等。
不阻断执行，追加友好提示。
适合非破坏性体验优化。
User Submit
 环境感知
注入git状态、时间等。
对用户透明，AI可见。
让AI始终感知项目上下文。
Stop Hook
 回复精简
AI回复过长时触发TLDR。
配合Skill实现质量审查。
防无限循环需双兜底机制。
设计哲学：不可判定问题
Bash命令安全性检测本质上是不可判定问题（类似停机问题）。无法穷举所有危险命令变体（rm、sudo rm、base64编码执行、脚本文件间接调用...）。 与其机械封堵逼AI绕路，不如提醒+自觉，给它退路它反而遵守规则。
Bypass 绕过机制
在bash命令末尾添加 # bypass 注释即可绕过拦截。Hook检测到bypass标记后，理解为"AI已经确认风险，坚持执行"——类似于手机管家的"我已知悉，继续访问"。
05 / 07
Hook × Skill
协同效应：从被动提醒到主动引导
Write Hook + 设计Skill
检测到写HTML/CSS时自动提醒加载设计规范，避免"AI拉屎审美"
 前端质量保障
Stop Hook + TLDR Skill
AI回复过长时自动触发精简，配合自定义TLDR规则生成针对性总结
 信息效率提升
核心技巧
Skill是AI主动调用（需要时才加载），Hook是被动触发（行为触发后才看到提醒）。 将两者结合：Hook劫持操作 → 注入提醒 → AI调用Skill → 规范执行，实现全自动质量控制闭环。
Submit Hook + 代码审查Skill — 每次提交前自动注入代码检查提示
Bash Hook + 安全检查Skill — 执行shell命令前强制走安全评审
Edit Hook + 格式化Skill — 每次写文件时自动提醒代码风格规范
06 / 07
核心洞察总结
Claude Code Hooks 的五大核心要义
Hook不是"又一堆规则"，而是一种从根本上改变AI行为约束方式的架构设计
!
传统的CLAUDE.md规则是"静态文档"——写在开头，等着被遗忘。 Hook是"动态守护"——在需要时出现，精准提醒。 这不是多了一种约束方式，而是一种范式的转变。
01
规则文件应精简
每条规则都需审视"是否有必要常驻上下文"，避免膨胀导致失效
02
关键约束迁移到Hook
安全约束从CLAUDE.md移到Hook，减少常驻上下文占用token
03
留退路比堵死更有效
AI被提醒后自觉纠正，而非想方设法绕过机械封堵
04
不同风险用不同层级
破坏性操作→阻断Hook，风格约束→提醒Hook，分级管控
05
Hook + Skill = 自动化闭环
组合实现强大的工作流约束，让AI既高效又安全可控
Hooks 的本质
在执行点注入提醒，利用位置局部性提升规则遵循率
→ 不是堵，而是引
  CLAUDE.md → 精简保留核心
  Hook → 安全/阻断类约束
  Skill → 主动按需加载
