方法一：LLM 直接分类
语义理解能力最强，适合处理模糊多样的用户表达
核心原理： System Prompt 中预设 N 个 Intent + 1 个"未知"兜底，LLM 根据 Query 语义输出匹配的 Intent 标签
关键缺陷： LLM 逐字生成（Auto-Regressive），即使使用大算力加速，其机制决定了速度天然慢于非生成式方案
适用场景： 用户表达高度多样化、模糊、多意图混合的复杂场景
方法二：规则匹配
速度最快、逻辑最稳，但需要精心设计匹配规则
三大优势
毫秒级响应：CPU 本地运算，不走网络
逻辑确定：每条规则 100% 可预测，无幻觉
易于调试：每条匹配路径可追踪、可复现
关键陷阱

用户说"我叫张三，我要请假"

如果只匹配到 "我叫" 关键词，就会触发身份识别意图

而丢失了"请假"这个真正的需求！

建议：匹配完整句式，而非单个关键词

方法三：BERT 语义匹配
类似 RAG 中的 Rerank 机制——Query 与 Intent 做语义相关性打分
为什么 BERT 更快？
LLM 是"预测下一个字→丢回去→再预测→..."的自回归过程；BERT 是双向理解，Query + Intent 拼接后一次前向传播直接出概率，无需逐字生成。
额外优势：可微调
创建几百上千条标注数据（Query-Intent 对），对 BERT 微调，让它深度适配你的业务场景。
注意： BERT 语义理解能力不及大模型，对于高度模糊或复杂的语义场景可能误判。

核心洞察总结
路由层思维
在 Query 和 Action 之间插入意图识别路由层，将模糊的自然语言请求精准分发到最合适的工作流。这是 Agent 架构从"大而全"到"专业分工"的关键转型。
混合方案最优
规则匹配（快且稳）→ BERT（均衡）→ LLM（强但慢），三者按确定性从高到低级联使用。没有一种方案是银弹，混合才能最大化性价比。
结构化输出必不可少
LLM 方案必须设计 Intent + Confidence + Complement 的完整 JSON 输出结构，配合Human-in-the-Loop机制处理低置信度和信息缺失场景。
Skills 即意图识别
Skills 索引文件就是 Intent 目录，Skill 选取就是意图识别，Skill 注入就是专业 Agent 的创建。两者是一体两面，现代架构已将二者无缝融合。
